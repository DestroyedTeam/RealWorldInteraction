# Windows 本机 CUA 重绘：RCU 只读观察

原生执行者是 Windows Codex `node_repl + @oai/sky`；观察者是 Mac 本任务实际
加载的 RCU `computer.discover/bind_window/observe/image`。没有终端 MCP 客户端
代替 RCU GUI 入口，观察期间 RCU `SendInput` 计数为 0。

用户先要求高频截图，后要求暂停，再明确要求约每秒一次观察新一轮绘制。暂停
请求已终止采样；新一轮重新选择新 Paint（PID 12116，HWND 0x506a4），没有
动旧草稿。第二轮只保留前台 Paint/原生 owner 关系内的窗口观察，不切换焦点。

## 实际看到的过程

- 空白 512×512 画布、三段相连试笔、黑底。
- 盾形从半边到闭合，随后顶弧、橙色 X、黑色裂缝与橙色碎片。
- 多张原始预览显示指针与蓝色光晕出现在笔画端点、工具栏和画布附近。
- 文件菜单展开另存为格式；之后标题变为 `windows-cua-nemessix - Paint`。

这证明离散采样时刻有设备侧视觉反馈和中间绘制状态，**不是高帧率视频**；
不能测出 Pointer 延迟或证明每一帧连续。保存/重开位于观察空档内，其证据来自
Windows 原始任务的工具输出及文件，不冒充由 RCU 连续拍到。

第二轮 RCU 保留 **126 个采样、17 个不同原始图像哈希**，12:57:25.109–
13:01:55.477 UTC；工具自产 1280 长边预览原样落盘，未绘制/后加 Pointer。
相邻采样中位间隔 1478 ms、P95 2127 ms；最大空档 82232 ms，包含批次之间的
本任务编排间隔和 Paint 非前台/对话框选择间隙。不能说“全程精确 1 FPS”。
observe+image 中位耗时 1441 ms、P95 1996 ms。高频 UIA/GDI 观察有负载，
不能从本次结果排除其对执行端的影响。

## Windows 原始任务计时复算

以原始 `task_started/task_complete` 为整轮边界，不采用报告中的阶段时间替代。

| 指标 | 第二轮实测 |
|---|---|
| 整轮 | 12:57:02.845–13:01:29.631 UTC，**266.786 s（4分26.786秒）** |
| 启动到图形绘制调用完成 | 122.732 s；当前用户要求不强迫每次保存，此阶段单独保留 |
| 首工具至重开确认 | 201.069 s；不含前置准备及后续报告，不能称为整轮 |
| 顶层工具 | 17 次，调用区间合计 34.413 s |
| 其中原生 node_repl 入口 | 15 次，Host 调用区间合计 31.525 s（与上一行重叠） |
| 顶层工具区间外 | 232.373 s，包含模型、调度、编排及输出，不是纯思考 |
| 输入 API 请求 | 79 drag、15 click（含一个双击请求）、5 press_key、1 type_text；按代码循环展开 |

关键代码中 41 次独立 drag 在同一 cell 顺序 await，含末尾观察的 Host 区间为
4.348 s。**不是一次持续按住的多点轨迹，也不是原生输入时延=4.348/41。**
绘制阶段有约 11–25 s 的工具间隔，重开后至报告调用还有 45.313 s 间隔。
因此可借鉴的是状态复用、有界批量动作和节点观察，不能只优化网络 RTT。

实际代码多次在同一 cell 复用截图 ID 后连续执行动作，偏离随包 guidance 的
“单次动作/立即观察”建议；报告作为行为实测保留，**不据此宣称该技能流程合规**，
更不将忽略新鲜度检查的做法直接复制进 RCU。

用户最新强调对照绘制与提示，不要求保存。因此上述保存证据仅记录已发生的
