## 3. 应保留的改进，不能因重构而丢掉

1. 原生身份、PID/birth/owner/session/desktop 的检查；对无法证明的窗口/坐标不猜测。
2. 同桌面跨协作进程 lease、私密文件/pipe 的访问约束、真实 peer 和 agent image 校验。
3. 调用取消、资源释放、部分输入和未知结果的显式记录，动作 reservation 的持久化与 dedup。
4. UIA/AX 的原生观察和有界回读、frame/图像哈希与视图映射。
5. 具体动作前的新鲜度/焦点/遮挡/必要文档检查；ACK 与结果验证分开。
6. 原生 Windows ABI、包识别/文件句柄、GUI subsystem、隐藏 IME 分类等已经有证据的局部修复应先做行为不变提取，不随任务状态机一并扔掉。

这些是可复用原语，不意味着当前实现不存在缺陷或已经通过所有平台测试。

## 4. 不应继续扩展的部分

- 固定八阶段协议、deployment 中的 Notepad/Task Manager Seed、`Approval.expected_ui_value`、全局业务 HOLD、必须 Oracle 成功才让服务正常结束的证明条件。
- 以“今天清理某进程”为理由在 `rwi-windows` 的基础 inventory API 中嵌入业务完成标准。应先提取通用 ProcessSnapshot/ProcessIdentity；匹配“全部不在了”的采样 oracle 属测试/调用方。
- 把 `computer.targets` 的业务失败回包当通用服务常态；正确服务应独立返回设备身份/可用性，失败只影响相应作用域。
- 在默认项目配置里注册 M1 smoke 等开发入口，或让插件绑定某次 run 的私有目录。
