# RWI：用户要求与可替代性验收清单

更新：2026-09-13；依据本任务用户输入、已批准 ADR 0002，以及 Windows 本机
Computer Use 两轮绘图和 Mac 原生应用记录。不是只按最近一条消息重新定义产品。

## 不变的产品约束

| ID | 用户要求 | 实施/验收约束 |
|---|---|---|
| R01 | AI 与多种 OS/设备沟通的通用基础设施 | 固定遵循 ADR 0002；Mac/Windows 是部署实例，不是写死的双端角色 |
| R02 | MCP、受控端独立运行，不因某个任务/窗口卡住 | 启动、配对、工具发现与传输不依赖应用名、业务 Stage、预期文本或 oracle |
| R03 | 无自有产品 UI、受控程序不能留黑窗 | headless agent；必要的 OS 授权及用户明确要求的输入状态反馈不等于控制面板 |
| R04 | 普通权限和管理员部署都支持 | 相同工具目录；会话/完整性级别和实际授权分别报告，Session 0 不冒充桌面会话 |
| R05 | 多 Host、跨 OS、VM、远程桌面、本机均考虑 | 明确设备/user/session/seat/desktop；VM 宿主画面与 guest 原生 agent 是不同 target |
| R06 | Mac 本机受控能力、Linux/Android/iOS 后续能力 | 实现与平台限制分别列明；不把架构预留当成实现；不为未来 IoT 堆空框架 |
| R07 | Codex 原生 MCP/plugin/skill，用户/Host 全局配置 | 安装件与身份放 checkout 外；新任务不依赖项目配置；旧 Host/catalog 不匹配必须显式修复 |
| R08 | GUI、SSH/terminal 并列互补 | 允许同流交叉执行与验证；分别证明通道身份与权限。终端部署/取证不算原生 GUI 输入 |
| R09 | 不再用 Python 客户端冒充原生 MCP 验收 | GUI 验收仅认 Host 实际加载的 RWI 工具；Rust 为生产后端，无隐形 Shell/.NET 桥 |
| R10 | 参考成熟实现，而非闭门写业务补丁 | 保留 CrossMacro 源码对照；结合 Codex Mac/Windows 的真实接口、行为和故障，不臆测 Cloud 实现 |
| R11 | Rust 模块架构及工程治理 | 根 workspace 为唯一可编辑源码；模块职责明确；行为与搬迁分开提交；功能分支、明确文件暂存 |
| R12 | Git、工作目录和交付物可协作 | 可提交/推送 DestroyedTeam；不 force push/release；不提交凭据、二进制、原始截图和本地设置；不在 work 创建开发副本 |

## 当前可替代性要求

|---|---|---|
| R13 | 真正鼠标/键盘能力 | 原生输入、正确坐标/焦点、独立效果验证；Windows 有实现和部分 live 证据，不等于跨平台全部完成 |
| R14 | 设备侧可见 Pointer 跟随与提示 | 实屏指针/光晕/按下释放反馈，不抢焦点、不拦截输入；静态图标或仅在截图后加标记不通过。常驻版已有原生 MCP/人工可见证据；用户选定 A1 菱形，批准可回滚开发版、UIOS 仅为设计依据。动效、现场 DPI 和输入到显示延迟独立验收，不能由离屏截图替代；详见 `../architecture/pointer-feedback.md` |

| R16 | 用真实安装的应用测试 | Windows Paint、Mac 原生绘图软件；浏览器 JS Paint 只计探索，不代替原生应用对照 |

| R18 | 分开验证 Mac/Windows Codex | 已确认实际入口不同；Windows 本机 `node_repl + @oai/sky`，Mac 统一 `cua`。不将 Mac→RWI 冒充 Windows 本机 CUA |
| R19 | 更精简的 MCP JSON、合适截图质量 | 常规只给相关变化与必要凭据，完整诊断按引用获取；保留错误/覆盖；不改用户分辨率 |
| R20 | 同时统计工具耗时与返回后的间隔 | 整轮墙钟、GUI 阶段、调用次数/大小、设备执行分层；混合模型/调度/编排时间不叫纯思考 |
| R21 | 查清“流式”、连接复用及稳定性 | MCP 外层、模型连接、本机 IPC、跨设备传输、原生输入节拍分别举证；不从 socket 名称推断视频流或双向模型流 |
| R22 | 实测不能拖到大量开发之后 | 每次行为改动安排最短真实应用检查；离线测试不能顶替 native Host 入口验收；不得只报 ACK 成功 |
| R23 | 高频观察要能退让、可停止 | 用户要求暂停立即停止；前台切到其他 app 不继续对固定屏幕矩形截图。只读也有 CPU/UIA 开销，公平基线需观察负载对照 |
| R24 | 保存、重开、截图等节点独立 | 2026-09-12 最新要求以绘制/提示对照为主，不强迫每轮都保存；已有保存/重开证据独立记录，不与成图或 Pointer 混算 |
| R25 | 清理 CrossMacro 是真实用例，不能写死进产品 | GUI 与 SSH 可分别验证持续重启/父进程行为；不在通用协议加入专属进程名或清理业务状态机 |
| R26 | 授权有效利用、少打扰 Control Center | 不再用短授权窗口耗在离线单测；当前 VM 无额外理论时限；关键节点沟通，不高频转发状态 |
| R27 | Agent 级常驻悬停，不是短暂操作提示 | 服务启动即显示；空闲/任务结束留在上次位置，操作时更新。不能只显示 800 ms，也不能闲时发送鼠标事件或拉回用户鼠标。系统桌面不可用不绕过 |
| R28 | OS 通用操作，包括系统弹窗、保存和资源管理器 | 2026-09-13 用户明确授权整个 Windows 桌面的普通应用；不设置 Paint 白名单。原生所有者弹窗、权威键盘焦点、返回主窗口及桌面快捷键已修复，并通过 Host MCP 另存 PNG 副本、GUI 重开和 Explorer 导航验证；不改写 R17 原独立任务当时重开失败的记录。未来 app 白名单独立配置，详见 `../architecture/windows-dialog-input.md` |

## 基于新对照的实施顺序

1. **设备侧 Pointer 反馈。** Rust 原生透明、不可激活/不可命中的常驻反馈层，
   服务生命周期驱动空闲显示，实际输入驱动位置/状态；失败/取消退回空闲，
   服务停止清理；不显示用户键入内容。必须处理
   反馈像素对截图 grounding 的污染，不能删除整个内容哈希/焦点校验来换流畅。
2. **观察用途分离。** 原生输入 grounding、只读图像观察和 UIA 语义查询不应
   总是捆绑。此次 RWI 观察中位数约 1.44 s，UIA 扫描属于需剥离的开销；纯图像
   观察返回不能直接当成获得任意输入授权的 frame。
3. **动作编排与资源边界。** 在设备节拍的单笔轨迹之外，支持有界、已确定的
   多笔操作序列；按动作校验目标/焦点/敏感元素，变化立即停止，不自动补播。
   不能简单复制对照任务“循环复用旧截图”的写法，跳过 RWI 的有效性约束。
4. **模型接口与输出。** 减少重复截图/全树/分页无关数据；操作对象、预览坐标、
   回执与后续细节引用统一；补原生 Host 新任务验收，避免旧 adapter 掩盖新能力。
5. **运行态复查。** 在明确分配的真实应用中做指针、连笔、Stop、窗口变化、
   普通/管理员、网络断开不重放、其他设备不受阻的验证。改动不靠业务 oracle 解锁。
6. **平台扩展。** 按同一能力协议补 Mac agent 的真实链路，再按 OS 能力逐项
   扩展 Linux/移动端/设备类型。任何未测平台都不宣布可替代。

初期不要求像素级复刻或全平台齐备；“基本替代”的最低线是：真实原生入口、
真实软件、可见反馈、连贯输入、有效停止/恢复以及可以复查的结果。一个成功
画稿、连接复用数字或离线绿灯都不能单独宣布与 Computer Use 打平。
