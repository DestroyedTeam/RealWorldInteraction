## 真实被测链路

`Mac Codex 中实际发现的新 RCU MCP 工具 → Rust guest 服务 → Windows 原生 API → 独立结果证据`

必须记录 Codex 端工具发现、真实工具调用、候选源/二进制 SHA、host/guest/session/desktop、原生窗口/控件身份和结果。

区分三条通道：

1. **布置环境**：安装候选、准备自有测试文件/夹具、布置窗口、执行可复现的故障注入。
2. **被测工具**：实际完成用户目标的操作只能由新 RCU 工具完成。
3. **独立核验**：读取实际控件/文件/原生日志，检查目标和诱饵都发生了什么。

辅助通道不能替新工具完成任务后冒充通过。RPC 测试脚本、固定步骤重放、模拟 fixture、真实 Codex 自主选择工具，分别报告，不相互替代。正常任务优先用 VM 已安装的常见应用；专用 Rust 原生测试夹具用于可重复极端情况，二者也分别统计。

## 评分与停止条件

- **完成度**：完成完整后置条件的任务数 / 实际启动的任务数；拆开未实现、环境阻挡、用户取消、安全停止和失败。
- **准确度**：正确窗口/元素/坐标/数据；错误目标写入和误报成功应为零，有一次就保留为失败，不能用平均分抵消。
- **合理度**：是否根据当前证据重观察、处理模态、遵从取消、选择有边界的恢复；不得靠强行夺回焦点或隐藏 fallback 提高完成率。
- **性能**：冷/热启动、采集/编码/传输、操作至确认、取消延迟、长时资源；模拟与真实数据分开。
- **恢复**：部分执行不确定时先核查；用户恢复后从当前状态继续。安全停止可以是正确行为，但不是任务完成。

未支持的操作记为 capability gap，未执行的场景保留空结果。不能把不敢执行所有动作、只读观察成功或者旧工具代做计为全链路通过。
